# 🔧 Технічне завдання на реалізацію вибору мови відображення інформації в Telegram-боті EarnAggregator

## 🏗️ Загальна інформація про реалізацію

### Мета реалізації:
- Додати опцію вибору мови інтерфейсу (interface language) в Telegram-боті, з підтримкою української (Українська) як поточної мови та англійської (English) як додаткової.
- Забезпечити динамічну зміну мови для кожного користувача, з збереженням вибору між сесіями (sessions) для персоналізованого досвіду (user experience).
- Інтегрувати багатомовну підтримку (multilingual support) без значного впливу на продуктивність бота, зберігаючи час відповіді (response time) в межах 0.5 секунди.
- Підтримати монетизацію через реферальні посилання (referral links), адаптуючи їх описи до обраної мови.
- Реалізація повинна відповідати загальній архітектурі проекту: модульність (modularity), кешування в Redis, зберігання в PostgreSQL, REST API на FastAPI, Telegram-бот на Aiogram 3.x.

### Джерела даних для реалізації:
- Результати глибокого дослідження: Аналіз документації Aiogram (docs.aiogram.dev), форумів (Stack Overflow, Reddit r/telegrambot), репозиторіїв на GitHub (наприклад, aiogram/i18n, Arustinal/fluentogram), YouTube-відео (наприклад, "Розробка Багатомовних Telegram ботів з aiogram i18n") та статей на Medium (наприклад, про middleware для i18n). Пошук охоплював англомовні (англійські), україномовні (українські) та російськомовні (російські) джерела, включаючи безкоштовні довідники (guides) та приклади коду (code examples).
- Ключові висновки з дослідження: Найкращий спосіб — використовувати i18n (internationalization) через Babel або Fluent з middleware для вибору мови; зберігати вибір в FSM (Finite State Machine) або БД; приклади на GitHub показують шаблони з gettext для перекладів (translations) та кнопками для зміни мови.

### Вимоги до реалізації:
- Підтримувати дві мови: Українська (default, поточна) та English.
- Зберігати вибір мови per-user (для кожного користувача) в FSM storage (зберігання) або PostgreSQL.
- Перекладати всі тексти (texts), кнопки (buttons), повідомлення (messages) та помилки (errors).
- Обробляти помилки з graceful degradation: при проблемах з перекладом використовувати default мову (Українська).
- Оновлювати мову динамічно без перезапуску бота.

## 📊 Аналіз системи вибору мови

### Основні компоненти для перекладу:
- Тексти повідомлень (message texts): Привітання (/start), описи продуктів (product descriptions), помилки.
- Кнопки та меню (buttons and menus): Навігаційні кнопки (navigation buttons), реферальні посилання.
- Команди (commands): Описи в /help, рекомендації (/recommendations).

### Повільні операції та оптимізація:
- Переклад не повинен додавати затримок: Використовувати lazy_gettext для відкладеного перекладу (lazy translation).
- Зберігання: FSM для швидкого доступу, БД для персистентності (persistence).

### Проблеми поточного стану:
- Відсутність вибору мови: Всі користувачі бачать тільки Українська.
- Відсутність i18n: Тексти hard-coded (жорстко закодовані), складно додавати мови.

### Цільові показники:
- Час перекладу: < 0.1 секунди на повідомлення.
- Об'єм даних: 1-5 КБ на мову в файлах перекладів.
- Масштаб: Підтримка 1000+ користувачів з різними мовами.

## ⚠️ Нюанси реалізації вибору мови

На основі глибокого дослідження документації Aiogram, форумів (Stack Overflow: приклади middleware для i18n, Reddit r/telegrambot: обговорення Fluent vs Babel) та GitHub (репозиторії з шаблонами як aiogram-template з multilanguage, fluentogram для Fluent синтаксису):

- **Middleware для вибору мови**: Використовувати FSMI18nMiddleware для зберігання мови в FSM; на GitHub в aiogram/i18n рекомендують для динамічної зміни. Альтернатива — SimpleI18nMiddleware для автоматичного визначення з user.language_code.
- **Формати перекладів**: Babel з gettext (.po файли) для простоти; Fluent (.ftl файли) для складних граматик (grammar), як в українській. На YouTube відео "Розробка Багатомовних Telegram ботів" показують Babel для Українська/English.
- **Зберігання вибору**: В FSM для швидкості, або БД для персистентності (persistence) між сесіями. На Stack Overflow радять комбінацію: FSM для сесії, БД для довгострокового.
- **Безпека та privacy**: Зберігати тільки language_code; уникати чутливих даних. На Reddit згадують GDPR для EU.
- **Масштабованість**: Кешувати переклади в Redis; на GitHub fluentogram приклади з caching для швидкості.
- **Помилки**: Fallback до default мови (Українська) при відсутності перекладу; логувати без блокування.
- **Персоналізація**: Автоматично визначати мову з Telegram, але дозволяти зміну кнопками (/lang).
- **Монетизація**: Перекладати реферальні описи; трекінг кліків незалежно від мови.

## 📊 Правила реалізації вибору мови

- **Мови для підтримки**: Українська (default) та English; додавати інші через .po/.ftl файли.
- **Переклад текстів**: Маркувати всі строки gettext (_("text")); використовувати lazy_gettext для фільтрів (filters).
- **Зберігання вибору**: В FSM per-user; синхронізувати з БД для відновлення.
- **Вибір мови**: Кнопки в /settings або /lang; автоматичний з user.language_code.
- **Формат перекладів**: Babel для простоти; Fluent для складних випадків (як множина в українській).
- **Оптимізація**: Кешувати переклади; асинхронний доступ.
- **Валідація**: Перевіряти наявність перекладу; fallback до default.

## 📁 Структура модулів для реалізації

- Шлях: yield-telegram-bot/bot/
  - utils/i18n.py: Конфігурація i18n (middleware, locales).
  - locales/: Файли перекладів (uk/LC_MESSAGES/messages.po, en/LC_MESSAGES/messages.po).
  - middleware/language.py: Middleware для вибору мови.
  - handlers/settings.py: Handler для зміни мови.
  - models/user.py: Модель для мови в БД.

## 🚀 Покрокова інструкція реалізації

### Крок 1: Підготовка
- Встановити Babel або fluentogram.
- Створити директорію locales для файлів перекладів.
- Витягнути тексти: pybabel extract для .pot файлу.

### Крок 2: Конфігурація i18n (i18n.py)
- Створити I18n з default_locale="uk".
- Налаштувати middleware (FSMI18nMiddleware).
- Зареєструвати в dispatcher.

### Крок 3: Переклад текстів
- Маркувати всі строки в handlers gettext.
- Створити .po файли для uk та en.
- Компілювати в .mo.

### Крок 4: Реалізація middleware (language.py)
- Перехоплювати update, витягувати мову з FSM або user.language_code.
- Встановлювати поточну мову.
- Зберігати зміну в FSM/БД.

### Крок 5: Handler для вибору мови (settings.py)
- Додати команду /lang або кнопки в меню.
- Змінити мову, зберегти, перезавантажити сторінку.

### Крок 6: Інтеграція з БД
- Додати поле language в таблицю users.
- Синхронізувати з FSM при старті.

### Крок 7: Тестування та моніторинг
- Тестувати переклади на обидві мови.
- Моніторити помилки перекладів.
